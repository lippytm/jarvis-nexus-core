## 1. Operating doctrine

**One source record -> many experiences -> many products -> many channels -> measured outcomes.**

The multiverse can be unlimited in story scope, time and space. Engineering and business work remains bounded, reviewable and evidence-aware.

Design laws:

- Unlimited universe; bounded mission.
- Evidence travels with every derivative.
- Human authority controls publication, financial actions and physical robotics.
- Reuse modular product genomes instead of creating disconnected products.
- Simulate before physical robotics or wearable deployment.
- Transform reviewed sources rather than rewriting facts independently per channel.
- Measure traffic, learning, product use, sales, commissions and costs as distinct outcomes.

## 3. AI Building AI / Jarvis governance

AI Building AI means AI-assisted design, testing, documentation and improvement of bounded tools and assistants. It does **not** mean uncontrolled self-replication.

Standard roles:

- Planner: mission and acceptance criteria.
- Researcher: sources, assumptions, contradictions and evidence gaps.
- Architect: interfaces, dependencies and failure modes.
- Builder: bounded implementation.
- Evaluator: independent findings.
- Reporter: evidence, changed files, tests, limitations and next action.
- Release Owner: authorized decision about deployment/publication.

Capability should improve through better tools, evidence, evaluation, memory contracts and permissions—not by maximizing agent counts.

## 4. Product Creation Machine

Every product receives a Product Genome including:

- stable product ID and version
- brand/division
- audience and need
- source record and source revision
- AI roles
- hardware/software/robotics roles
- security and data classification
- evidence gate
- media derivatives
- business model
- rights/accessibility requirements
- status and next action

Factory sequence:

1. Idea intake.
2. Research.
3. Canon/requirements lock.
4. Build the smallest useful artifact.
5. Evaluate claims, code, accessibility and failure modes.
6. Derive medium-specific editions.
7. Package metadata, captions, rights and manifests.
8. Distribute only to approved destinations.
9. Measure actual outcomes.
10. Iterate by version rather than silently rewriting history.

## 8. Robotics and humanoid robotics

Mission phases:

Perception -> Planning -> Execution -> Evaluation -> Transfer -> Human-authorized physical release.

Human + robot + AI missions divide responsibility:

- human: goals, tradeoffs, ethics and ambiguity
- robot: repeatable simulated or physical procedures
- Jarvis: evidence, next checks and documentation
- evaluator: comparison against acceptance criteria

Simulation success is not physical readiness.

## 15. Evidence, security and privacy

Evidence states:

source_linked, owner_reported, planned, fictional, open_question, verified, tested_local, blocked_unverified.

Security principles:

- least privilege
- separate read/draft/review/publish/financial/physical permissions
- no secrets in public artifacts
- explicit device pairing and revocation
- independent robot safety controls
- imported AI output is data, not authority
- release records retain version, source, review and rollback evidence

Diary content defaults private; public adaptations are separately selected.
